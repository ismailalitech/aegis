Found on the way:
  - tee.elf cannot be loaded as an ELF: OP-TEE's start-up reads __init_size at __data_end, past the ELF's file
    data (gen_tee_bin appends it to tee-raw.bin only). Loaded from the ELF it read 0xFFFFFFFF and took an alignment
    fault in copy_init (ESR_EL1 0x96000021 at 0x60000078, read over JTAG). BOOT.BIN uses tee-raw.bin at 0x6000_0000.
  - a JTAG test must start from power-on: Linux 6.12 powers down unused PM domains, which stay off across
    "rst -system", and the FSBL's init_serdes then stalls.

What phase A shows: the protocol, the ML-DSA-65 key, the ML-KEM exchange and the KMAC session now live in the
secure world; Linux holds none of them and only carries lines. What it does not: the key comes from OP-TEE's
fixed development HUK, the same on every chip (hence "trustzone-devkey"), and nothing is measured. Phase B binds
the key to the PUF and hands the boot chain's measurements to OP-TEE; phase C keeps Linux away from the CSU and
from OP-TEE's memory (today only the device tree does).
