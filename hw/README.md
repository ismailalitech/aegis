# aegis_pqc: Keccak-f[1600] and NTT accelerator (PolarFire SoC fabric)

`aegis_pqc` is an APB3 slave for the fabric of the MPFS095T. It contains:

- a Keccak-f[1600] permutation unit (24 rounds, one round per clock), and
- a 256-point NTT / NTT^-1 unit for ML-KEM (q = 3329) and ML-DSA
  (q = 8380417), one butterfly per clock.

It implements the FIPS 203/204 NTT and the FIPS 202 Keccak-f permutation. In
simulation it matches the reference models in `model/`. It is not
FIPS-validated.

This page was written before synthesis. Since then the core was built into
the PolarFire fabric as design dv101 (16 November 2026: timing met at 50 MHz,
about 11,844 4LUT, 3,087 DFF, 2 LSRAM and 26 Math blocks) and checked on the
board against the C references and liboqs's known answers
(`docs/phase2-notes.md`). Its successor, which keeps the sponge in the fabric
(`rtl/aegis_sponge.v`, `rtl/aegis_pqc2.v`), has run on the board since
17 November 2026: `docs/accelerator-v2.md`. The "Not synthesized" and "Not
tested on hardware" limits below are the state before that.

All RTL is plain Verilog-2001 (it compiles with `iverilog -g2001 -Wall`). It
uses no vendor primitives: the RAMs, ROM and multipliers are inferred. There
are no `include` files and no `$readmemh` in `rtl/`.

## Integration

- Ports: `PCLK PRESETN PSEL PENABLE PADDR[31:0] PWRITE PWDATA[31:0] PRDATA[31:0] PREADY PSLVERR`.
  Only `PADDR[7:2]` is decoded. `PREADY` is tied to 1 and `PSLVERR` to 0.
- Slot: 256 bytes at 0x40000E00 (FIC3 APB). Everything runs on PCLK (50 MHz).
  There is no clock-domain crossing.
- Reset: `PRESETN` is an asynchronous, active-low reset. It clears the
  control registers and the Keccak state. The NTT RAM is not cleared.
- Read data is combinational from `PADDR` and registers during the access
  phase. Writes take effect on `PSEL & PENABLE & PWRITE`.

## Register map

| Offset | Name | Access | Description |
|---|---|---|---|
| 0x00 | ID | R | 0xAE150001 |
| 0x04 | CTRL | W | bit0 KECCAK_START, bit1 NTT_FWD_START, bit2 NTT_INV_START, bit8 NTT_MODE (0 ML-KEM, 1 ML-DSA; latched on an NTT start). A start is ignored while its unit is busy. If bit1 and bit2 are both set, the forward transform runs. Reads 0. |
| 0x08 | STATUS | R | bit0 keccak_busy, bit1 ntt_busy, bit4 keccak_done (sticky, cleared by an accepted KECCAK_START), bit5 ntt_done (sticky, cleared by an accepted NTT start), bit8 NTT mode of the last accepted start |
| 0x0C | KECCAK_CYCLES | R | PCLK cycles that keccak_busy was high for the last permutation (counts up while busy) |
| 0x10 | NTT_CYCLES | R | PCLK cycles that ntt_busy was high for the last NTT / NTT^-1 (counts up while busy) |
| 0x14 | NTT_INDEX | RW | Coefficient index 0..255 (bits 7:0). Writes are accepted while busy. |
| 0x18 | NTT_DATA | RW | coefficient[NTT_INDEX], bits 22:0. Every read and every write increments NTT_INDEX (mod 256), even while ntt_busy. While ntt_busy, writes are dropped and reads return 0. |
| 0x38 + 8i | LANE_LO(i) | RW | Keccak lane i (i = x + 5y, 0..24), bits 31:0 |
| 0x3C + 8i | LANE_HI(i) | RW | Keccak lane i, bits 63:32. While keccak_busy, writes are dropped and reads return 0. |
| others | - | - | Read 0; writes are ignored |

Lane i holds state bytes 8i..8i+7, little-endian, as in FIPS 202.

**Lane base: 0x38, not 0x40.** 25 lanes take 200 bytes (0xC8). Starting at
0x40, they would end at 0x107, past the end of the 256-byte slot: lane 24
would alias offsets 0x00 to 0x07 of the next slot. The lanes therefore start
one lane earlier, at 0x38, and end exactly at 0xFF. Offsets 0x1C..0x37 are
still free. The base is one constant in `rtl/aegis_pqc.v` (`W_LANE0`),
`sw/aegis_pqc_regs.h` (`AEGIS_PQC_LANE_BASE`) and `tb/gen_vectors.py`
(`LANE_BASE`).

### Use

Keccak-f[1600]:

1. Write 50 words to `LANE_LO(i)` / `LANE_HI(i)`.
2. Write `CTRL = 1`.
3. Poll until `STATUS` bit0 is 0.
4. Read the 50 words.

NTT (mode m = 0 for ML-KEM, 1 for ML-DSA):

1. Write `NTT_INDEX = 0`, then write 256 values to `NTT_DATA`. Values must be
   canonical, i.e. in [0, q).
2. Write `CTRL = 2` (forward) or `CTRL = 4` (inverse), with `m << 8` added.
3. Poll until `STATUS` bit1 is 0.
4. Write `NTT_INDEX = 0`, then read `NTT_DATA` 256 times.

The data stays in the core, so a forward transform can be followed directly
by an inverse one. The two units are independent: one `CTRL` write can start
both.

## Design notes

**Keccak.** The state is a 1600-bit register. A combinational round function
(theta, rho, pi, chi, iota) is applied once per clock while busy, so a
permutation takes 24 clocks. The round index selects the round constant.

**NTT storage.** The 256 coefficients are held in two 128 x 23 simple
dual-port RAMs. Coefficient i is in bank `^i` (the parity of the 8-bit index)
at address `i[6:0]`. The two operands of a butterfly, j and j + 2^l, differ
in exactly one bit, so they always sit in different banks. Each bank then
needs one read and one write per clock, and one butterfly is issued every
clock.

**Schedule.** Butterflies are issued in the order of the standards' loops,
128 per layer: 7 layers for ML-KEM, 8 for ML-DSA. For butterfly `bf` in a
layer with len = 2^l, the address generator computes:

- `j = (bf & (2^l-1)) | ((bf & ~(2^l-1)) << 1)`
- the twiddle index `k = {1, bf} >> l` (forward) or `{1, ~bf} >> l` (inverse)

The k formula reproduces FIPS 203/204's k++ / k-- sequence. No stalls are
needed between layers. A layer reads a coefficient at least 57 clocks after
the previous layer wrote it, while the pipeline is 8 clocks long
(`model/ntt_hw.py` checks this for all four transforms).

**Butterfly.** It uses two `aegis_modmul` instances, A and B:

- Forward (Cooley-Tukey): `pA = b*zeta`, `pB = a*1`; `a' = pB + pA`,
  `b' = pB - pA`.
- Inverse (Gentleman-Sande): `pA = (b - a)*zeta`, `pB = (a + b)*zB`;
  `a' = pB`, `b' = pA`. `(b - a)*zeta` equals FIPS 204's `(-zeta)*(a - b)`.
- Final scaling of NTT^-1: in the last inverse layer (len = 128), zeta is
  replaced by `zetas[1]*f` (ROM entry k = 0) and zB = f, with f = 3303 or
  8347681. The final multiply by f is therefore merged into that layer, and
  NTT^-1 takes the same number of clocks as NTT.

**Pipeline** (clocks after issue):

| Clock | Stage |
|---|---|
| 0 | address generation |
| 1 | RAM and ROM read |
| 2 | bank swap and pre-add (inverse) |
| 3-6 | modmul |
| 7 | post add/sub and bank swap |
| 8 | RAM write |

**Reduction.** Barrett reduction (HAC Algorithm 14.42, base 2):

- `q1 = x >> (n-1)`
- `q3 = (q1*mu) >> (n+1)`, with `mu = floor(2^(2n)/q)`
- `r = (x - q3*q) mod 2^(n+2)`
- then two conditional subtractions

Here n = 12 and mu = 5039 for ML-KEM; n = 23 and mu = 8396807 for ML-DSA.
`model/ntt_hw.py` checks every x in [0, (q-1)^2] for both moduli. It does so
block by block: q3 is constant inside each block of 2^(n-1) values of x, so
checking both ends of a block covers every x in it. The result is
0 <= r < 3q and r = x mod q. The largest r is 2.083q for ML-KEM and 1.506q
for ML-DSA, so the second subtraction is only ever needed for ML-KEM.

## Verification

Run from the repository root:

```
hw/tb/run_all.sh            # about 65 s
hw/tb/run_all.sh --fast     # skips the ~6 s exhaustive ML-DSA Barrett sweep
```

The script:

1. runs the three model self-tests;
2. checks that `rtl/aegis_ntt_rom.v` matches `gen_rom.py`;
3. regenerates the vectors (fixed seed);
4. compiles both testbenches with `iverilog -g2012 -Wall` and treats any
   compiler warning as a failure;
5. runs both testbenches with `vvp`. Each must exit 0 and print its PASS line.

Python is taken from `$PYTHON`, else `../.venv/bin/python`, else `python3`.
It needs only the standard library.

Results of the last run (Icarus Verilog 12.0, Python 3.12.3):

| Check | Result |
|---|---|
| `keccak.py` | All-zero state gives lane 0 = 0xF1258F7940E1DDE7. 300 random messages of 0..2000 bytes (259 multi-block) hashed with SHA3-256, SHA3-512, SHAKE128 and SHAKE256 on top of the model equal `hashlib`. |
| `ntt.py` | 100 random vectors per scheme: NTT^-1(NTT(x)) = x and NTT(NTT^-1(x)) = x. ML-DSA: 100 pointwise products equal schoolbook a*b mod (X^256+1, q). ML-KEM: 100 MultiplyNTTs (Alg. 11/12) products equal schoolbook. Zeta tables spot-checked against FIPS 203 App. A and FIPS 204 App. B. |

Also checked: ID, reset values, unmapped offsets, writes to read-only registers, NTT_INDEX masking, auto-increment and wrap, 23-bit data, STATUS bits, both cycle registers, dropped writes / zero reads / ignored starts while busy (both units, both modes), Keccak and NTT running at once, and both start bits set. 380,925 APB transfers, 114,294 checks, 0 errors. |

As a one-time check (not part of `run_all.sh`), 11 deliberate faults were put
into copies of the RTL. Examples: a wrong round constant, f, the last-layer
flag, mu, the missing second subtraction, NTT_INDEX increment, busy gating,
done one clock early, restart while busy. The testbenches caught 10 of them.
The eleventh (ML-DSA mu reduced by 1) is functionally equivalent: r stays
below 2.51q and the corrections still give the right result. A larger mu
error is caught.

## Measured cycle counts

From the `KECCAK_CYCLES` / `NTT_CYCLES` registers in simulation:

| Operation | PCLK cycles | At 50 MHz |
|---|---|---|
| Keccak-f[1600] | 24 | 0.48 us |
| ML-KEM NTT or NTT^-1 (7 x 128 butterflies + 8) | 904 | 18.08 us |
| ML-DSA NTT or NTT^-1 (8 x 128 butterflies + 8) | 1032 | 20.64 us |

These counts cover only the time the unit is busy. Moving data over APB costs
more:

- Keccak: 50 writes and 50 reads per permutation.
- NTT: 256 writes and 256 reads per transform.

On the board, the CPU's access time to the FIC3 APB will dominate. That time
has not been measured.

## Limits

- **Not synthesized, not timed.** No synthesis, place-and-route or timing has
  been run, so there is no resource estimate and no timing figure. The design
  is pipelined for 50 MHz:
  - modmul stages: product, q1*mu, x - q3*q, corrections;
  - NTT address generation and RAM data both go through registers.

  The paths most worth checking in Libero are:
  - the modmul stage-3 constant multiply plus 25-bit subtract;
  - the Keccak round (about 4 LUT levels, but 1600-bit wide);
  - the combinational APB read path (`PADDR` -> 50-word lane mux ->
    `PRDATA`), which goes through the FIC3 interconnect.
- Not tested on hardware.
- NTT inputs must be canonical (< q). Other values give unspecified results;
  no error is flagged. Outputs are always canonical for canonical inputs.
- `NTT_INDEX` also increments on `NTT_DATA` accesses made while ntt_busy
  (they are dropped or return 0). An `NTT_DATA` read whose setup phase falls
  in the last busy clock also returns 0. Software that polls `STATUS` first
  never sees this.
- PADDR[1:0] are ignored, so byte offsets are rounded down to the word.
- No side-channel countermeasures. The cycle counts do not depend on the
  data, but power and EM are not addressed.
- The Keccak state and the NTT coefficients can be read by anything that can
  access the APB slot (e.g. root through `/dev/mem` or UIO).
- The twiddle ROM and the RAMs are left to synthesis inference (LSRAM, uSRAM
  or logic, as the tool chooses). How Synplify maps them has not been checked.
